# 验收与排查

## 自动验收

从生成的项目目录运行 `python verify.py`。使用非默认端口时传入 `--port 8790`。公网使用 `python verify.py --live`，读取记录的域名与独立生产口令。两种模式都实际读取每个文件，准备流量预算时按所有文件大小之和，再加一份续传样本计算。按文件输出名称、字节数和 SHA-256。测试数据清理仅针对本次生成的随机备注和卡密哈希。如果进程被强行终止，后台可能留下带有 `qa-` 随机备注的记录，清理时要逐条匹配。

| 检查 | 通过条件 |
| --- | --- |
| 后台权限与默认额度 | 匿名发卡被拒绝。管理员登录后按表单默认值直接发卡，领取结果中的每个配额都与设置相符。 |
| 兑换与复制内容 | 可复制文本含正确领取地址、卡密和教程。另一独立会话兑换同一张卡密得到 409。 |
| 直链与完整性 | HEAD 返回正确长度。GET 在原签名地址直接返回附件，完整 SHA-256 与输入一致。对 ZIP、APKG 和 Office ZIP 格式另核对归档 CRC。 |
| 下载计数 | HEAD 和明确标记的预取不扣次。同一测试文件配额设为 1，并发两次从头下载恰好一次成功，另一次得到 409。其他文件继续独立验证。 |
| 发卡后调整与续传 | 调高一个文件的上限，先请求第一个字节，再以返回的 ETag 和 If-Range 请求余下部分，合并后的哈希正确，两段只计一次。单字节文件无需分段。 |

## 浏览器操作验收

项目另附可选脚本 `verify_browser.py`。在已有 Playwright 的 Python 环境执行 `python -m playwright install chromium`，然后运行 `python verify_browser.py`（公网加 `--live`，指定已安装的 Chromium 路径可加 `--executable`）。若环境尚无 Playwright，可在项目虚拟环境安装 `python -m pip install playwright`。脚本在 320 px 触屏和 1440 px 桌面视口读取真实剪贴板，检查手机布局和复制期间的请求。

手工验收时，用桌面窗口和手机触摸尺寸分别完成一次：打开管理路径登录；检查文件名和额度；生成卡密后点击「复制卡密和领取说明」，把剪贴板内容粘贴到文本框核对。用独立浏览器会话打开消息中的领取页，输入卡密，领取并复制一个链接。确认出现「复制成功」、地址栏停留在领取结果页、浏览器没有发出文件正文请求。再在外部客户端使用该链接，刷新结果页核对剩余次数。小屏上检查长文件名、额度输入框、复制按钮及展开的发放记录能正常阅读和点击。在线自动验收测试 HTTP 行为，实际视觉与剪贴板使用浏览器另行验证。

## 常见现象

- 下载器提示 ZIP 文件尾缺失时，查看状态码、Content-Type、Content-Disposition 和实际哈希。HTML 预览页、拒绝访问页面或中断的文件都可能有相同的扩展名。
- 点击复制没有成功提示时检查 HTTPS、剪贴板权限和浏览器限制。模板提供选中文本的回退方式。
- 链接被转发后，共用原卡密的该文件额度。聊天预览工具如果真正读取正文，服务器会计为开始下载。已经保存的副本可以在站外使用。
- 首次有效 GET 扣次；限定范围从零开始也是新下载。支持单段 bytes 范围，一小时内通过下载 Cookie 或 If-Range 续传。缺少续传证明或超出已记录的位置可能返回 416，已过期返回 410。卡密重复兑换和下载额度耗尽都可能返回 409，结合请求路径区分。
- 文件暂不可用时检查 Worker 的 FILES 绑定、分块键、D1 绑定及部署版本。第一块缺失会在扣次前返回 503。传输已经开始后断线，以续传能力恢复，永久失败可由管理员根据已用次数调整额度。
