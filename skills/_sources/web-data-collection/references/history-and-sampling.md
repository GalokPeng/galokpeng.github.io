# 历史数据与抽样

## 区分两种历史任务

**查过去发布的内容。** 可从网站档案、带日期的 RSS 或站点地图、官方导出和已有研究数据发现候选。使用用户要的日期，例如评论时间、首次发布、公告生效或交易发生。

**查网页在过去是什么样。** 例如某月的真实搜索结果、目录页中的价格、旧版政策正文。查 Internet Archive 的 Wayback Machine、Arquivo.pt、相关研究存档或带采集时间的数据集。当前结果的内容发布日期只能证明内容的日期，无法证明旧结果页当时显示的项目。

## 从历史线索到证据

1. 用索引按域名、路径、关键词、地区版本和日期找候选。索引时间戳、URL、摘要或抓取成功状态只能作为线索。需要正文时，回放确切快照或打开保存的原始记录。
2. 对照最终回放地址或来源提供的时间戳，识别跳转到其它抓取日期、空页、验证页、只剩导航的页面。存在正文时提取该场景真正的记录字段，例如搜索结果标题、商品价格的币种、政策版本号。仅有线索的条目可记录在核验清单。
3. 对不同地区、时间段、桌面或移动快照使用适合实际正文结构的提取规则。结果为空时，抽查正文是访问失败、网页确实为空，还是结构更新造成漏读。补查站点可替代路径、其它档案或带采集时间的保留数据。不同内容类型混用时，确认仍在用户范围内，并标明类型。

## 按月配额与证明覆盖

- 列出所有预期分组和月份，包含没有任何候选的组。默认以可核验的记录作为候选池。不同日期的价格快照可属于一个商品，历史搜索的去重键可用标准化的查询词。按用户所定义的记录单位决定键。
- 用户只要求固定配额时，可以对月内日期做均匀分布的优先次序，来源稀疏时接受相同日期的不同记录。用户要求随机或分层随机时，先明确候选总体、分层字段和种子，按对应方法抽取，并说明候选覆盖带来的偏差。
- 补录已有成品时保留原样本，从每组缺口计算需要的新增条数。验证新旧数据的去重键，写入后重新统计每组。每组 5 条且有 7 站点、58 个月时，验收要同时确认 406 组各有 5 条，合计 2,030 条。

## 可选命令行工具

需要从已核验候选做新的月度配额样本时，可用 [monthly_sample.py](../scripts/monthly_sample.py)。它只用 Python 3.9+ 标准库。候选文件采用 UTF-8 JSON Lines，每行一个对象，分组、日期和稳定去重键使用字符串。先按任务约定时区归一化日期，程序按输入日期的日历月份分组。筛选后的记录保留所有原字段。

```text
python scripts/monthly_sample.py verified.jsonl --group-field site --date-field captured_at --key-field record_id --group Alpha --group Beta --from 2024-01 --through 2024-06 --per-month 5 --samples sampled.jsonl --coverage coverage.json
```

在技能目录运行上述命令，或使用技能中脚本的完整路径。命令输出抽样 JSON Lines 和覆盖 JSON，覆盖结果包含候选数、去重后候选数、已选数量和缺口，包含零候选的月份。满足所有配额时退出码为 `0`，存在缺口但已写出结果时为 `1`，输入或参数错误时为 `2`。该工具适用于重新抽样。已有成品的增量补录应把原有样本及其去重键纳入缺口计算。
