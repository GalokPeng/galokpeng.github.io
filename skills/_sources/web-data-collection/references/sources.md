# 来源定位和翻页

## 按页面形态选方法

| 形态 | 采集方法 | 核验点 |
| --- | --- | --- |
| API、导出、RSS 或站点地图 | 用公开接口或官方导出读取结构化数据。站点地图可定位详情页，必要时再读原正文。 | 接口参数和用户的语言、日期、筛选范围一致。站点地图的 `lastmod` 通常是变更时间，发布日期需要页面或数据源支持。 |
| 列表、表格、详情页 | 先查看语义 HTML、表头和结构化数据，再按记录容器解析。详情页缺失时保留列表实际支持的字段与来源。 | 把标题、链接和其它字段从同一个记录容器提取。处理换行单元格、合并表头、相对链接、单位和不同语言标签。 |
| 动态页面、无限滚动、交互筛选 | 使用可用的浏览器或连接器操作正常的页面。公开的页面数据或内嵌 JSON 能支持所需字段时，可用其批量处理，并抽查界面。 | 明确加载结束与没有结果的差别。确保滚动中加载的每一批都被保存，尤其是只渲染可见区域的列表。 |
| PDF、图片或图表 | 优先用来源提供的数据表、下载项、文本层、图表对应数据。必要时从可读图表或 OCR 转录。 | 核对页码或图表、单位、数量和关键字段。注明从图像读出的近似值以及原图无法确认的值。 |

使用站点允许的访问渠道。公开页和已授权会话按实际可用方式处理。表单、登录或权限可能需要用户操作。403、验证码和登录墙可以促使切换到正式导出、已授权连接器或其它同等证据。遵循来源的分页、限流和重试约定。

## 全量采集与续跑

- 分页时跟随实际 `next` 链接、游标或“加载更多”状态，读取来源公开的总数。直到确认到达终点。保留页号和最后成功游标，遇到重复游标、页面循环或总数不一致时检查分页参数。
- 对持续变化且分页会移动的列表，优先使用支持稳定排序和行 ID 的接口，或以日期窗口分批，用原生 ID 去重。记录采集时间和筛选条件。仅能取得当前可见范围时，交付时写明覆盖范围。
- 最好用原生 ID 或经核验的规范链接作为主键。URL 的某些查询参数可能决定页面内容，确认语义再去掉跟踪参数。合并多个来源时，优先保留支持更多字段的记录，并保留来源差异。
- 如需恢复进度，将映射规则、游标、成功记录、重试和失败原因保存在工作区。便于追加的 JSON Lines 可作为中间格式。保存原始响应前确认确有排查或复核需要。

## 示例

采集公开目录里的“名称、地区、成立日期”。先验证目录提供的筛选和分页，再用详情页确认成立日期。目录列表若仅有名称和地区，保留这两列及链接，成立日期缺失留空。最终核对目录所报总数和去重后的记录数，并标出详情页不可访问的记录。
