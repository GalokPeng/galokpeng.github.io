# 从本地样例验收到官网体验

## 使用同一组可辨认的样本

用虚拟文件名、合成便签、纯色块或自有媒体作为固定夹具。在画布中画两条相距足够远的粗线，将其中一条中段擦掉。下载 PNG 并解码，验证底色、残留笔迹和擦掉位置。对抗锯齿边缘采用容差，在纯色内部优先做精确比较。录制样本中途改变一个明显可见的色块，这样能区分真实视频和只记录到第一帧的文件。

## 与用户操作相同的入口

| 情况 | 操作与观测 |
| --- | --- |
| 首次进入、最小化、重入 | 在官网外层找到 iframe，点击真实快捷方式或任务栏；检查窗口实例数、草稿和焦点。直接打开桌面路由作为第二个入口。 |
| 精准与可达性 | 用鼠标、触摸和键盘操作。测试窄屏、桌面、非整数缩放、深浅色、长标签、IME 和 reduced motion。按钮有名称和焦点样式。检查右下角菜单是否留在可视区。 |
| 异步竞态 | 延迟素材 A 的响应，立刻选择 B；之后 A 成功、失败或取消，B 均应保持。模拟 404、离线、缺失总长度、损坏原件和编解码器不可用。 |
| 截屏、标注、长图 | 比对选区像素尺寸与标记位置；撤销与重做后再次导出。长图测试重复帧、半屏重叠、无重叠的主动换页和首屏直接完成。 |
| 录制与清理 | 录两次，中间取消一次，检查结果文件与实际 MIME、尺寸和帧内容。关闭窗口或离开路由后检查 tracks、播放实例、计时器与对象 URL 的释放。 |
| 身份与范围 | 公开页面只呈现合成内容或有权展示的素材。虚拟文件删除只作用于演示状态，控制展示给访客的设备权限。 |

声明支持某设备或浏览器时，在对应环境走通关键路径。有触摸模拟测试时标明模拟环境。视觉像素比对使用相同视口、DPR、字体、主题和参考版本，给时钟、光标闪动、视频帧设定固定时间或遮罩。处理异步行为要等待可信事件或可见结果；固定 sleep 适合主动制造竞态，不能单独证明操作完成。

## 性能和交付

- 冷缓存测从导航到**可执行第一个动作**的时间，分开记录 HTML、交互代码、光标和首张可播放画面的耗时。再测试温缓存。不要用一次快网测量代表所有用户。
- 首屏尽早出现可工作的窗口。把截屏编辑器、导出编码器等大模块留到需要时加载。若往返延迟占主导，可将小索引或关键光标内嵌到构建出的 HTML；用传输字节和首次交互时间比较得失。内嵌 JSON 记得转义可以终止 script 标签的字符。
- 同一场景持续拖动或作画时看帧时间；反复打开和关闭媒体后检查活动解码器和内存变化。装饰动画减少布局读写。优先复用画布和缩略图，把对象 URL 的回收与资源所有者放在一起。
- 本地用真实 HTTP 路由验收相对路径和模块 MIME。上线后从用户实际域名重新打开**宿主页**。检查 iframe、子路径、主题样式、媒体响应、CORS、缓存版本和下载入口。允许离线启动的演示要测断网及缺失资产时的反馈。只交付本地包时，用解压后的文件运行同一回归。
- 验收记录应指向核对过的版本和产物，列出真实运行环境、通过路径、尚未验证的项目与实际限制。用户要求的安装版、官网和独立样例可以有不同发布节奏。

随包 [回归脚本](../scripts/check_starter.py) 用独立 HTTP 服务测试随包样例。结构检查和 ZIP 完整性说明入口可读，浏览器回归用来确认交互真的生效。
