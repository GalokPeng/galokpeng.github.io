# 把桌面软件做成网页里的可操作体验

收到“把这个软件放到官网上让人试用”这类任务时，先弄清访客要完成的操作、参照版本和最终交付位置。沿用目标站点的技术栈。以下路径都相对于本 Skill 的目录，可由任何能读文件的 Agent 使用。

## 从一个可复验的操作开始

1. **找依据。** 有指定版本时打开软件或读取对应源码，核对工具栏、快捷键、资源和测试。用合成内容记录动作前、动作中、动作后和取消后的画面。只有行为描述时，直接以用户确认的操作为依据，采用合成素材并说明视觉假设。只有截图时，把不可见的行为列作待确认项。
2. **写功能对照。** 每项写清入口、输入、状态变化、可见结果、实现范围、证据。优先选择访客最想试、能产生明确结果的一条路径。例：点素材 B 只改变预览；点“应用”后桌面才换成 B；预览加载期间切回 A，B 的迟到响应不能覆盖 A。
3. **选择实现方式。** 窗口、菜单、拖放和图像编辑通常可在浏览器本地实现。原生核心已有可移植的计算库时，可评估用 WebAssembly 复用。若交付要求运行原封不动的本机程序、驱动或系统服务，另行评估远程会话及其服务成本。把依赖操作系统的动作写入体验说明，按用户授权决定是否接入真实设备。
4. **做通一条完整路径，再扩展。** 把官网外壳、体验桌面、应用状态和渲染分开。先走通打开应用 → 改变状态 → 查看或导出结果。按参考行为继续验证最小化恢复或关闭重开，分别核对草稿和焦点。鼠标、触摸、键盘都从同一组业务动作进入。逐项补齐原版的提交时机、失焦、右键、撤销、错误与恢复。
5. **以输出验收。** 比对关键状态的画面，验证像素、文件、媒体播放或数据状态。记录已实现、浏览器内模拟、安装版专属、尚未验证的项。需要上线时，再检查正式域名上的完整入口和一项真实输出。

## 运行一个完整的小例子

[桌面样例](assets/starter/index.html)用本地 HTML、CSS、JavaScript 实现“色卡画板”。它演示独立桌面、快捷方式、可拖动窗口、预览与应用、笔迹与橡皮、撤销与重做、PNG 导出及可选的画布录制。导出范围是画板。将这些模块移植到目标应用时，用原版素材和动作替换色卡与画笔。

在本 Skill 根目录运行以下命令，再打开 `http://127.0.0.1:8000/`。可换用项目现有的静态服务器。

```sh
python -m http.server 8000 --bind 127.0.0.1 --directory assets/starter
```

[浏览器验收脚本](scripts/check_starter.py)会自行启动临时本地服务器和无头浏览器。装有 Python Playwright 与 Chromium 时运行 `python scripts/check_starter.py`；有本机 Chrome 时可加 `--channel chrome`。样例本身不依赖 Python 包、CDN、账号或外部服务。改造已有站点时，只迁入任务所需部分。
