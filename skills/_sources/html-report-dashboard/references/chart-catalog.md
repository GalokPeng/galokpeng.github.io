# Select charts by analytical question

Check the grain, comparison population, variable type, order, series count, and units first. Use the smallest display that answers the question. A readable value table or one sentence is often enough. If several charts are needed, each should answer a different question; repeated views are useful only when they serve distinct tasks, such as a profile plus exact lookup.

| Reader question | Preferred display | What to specify / avoid |
|---|---|---|
| Which segment is largest, where is the gap? | Sorted horizontal bars; grouped bars or aligned dots for few series; table for exact lookup | Bars start at zero; show counts and denominators. Use small multiples instead of many nearly indistinguishable series. |
| How has a measure changed? | Line for ordered time; slope/dumbbell for two checkpoints; uncertainty band if justified | Preserve temporal spacing and gaps. Unordered experiment versions are not a time series. Use matched populations or clearly label changes in coverage. |
| How does the mix differ? | Stacked bar for totals plus mix; 100% stack for shares; grouped bars for precise category comparison | Same category order and units. Label row n and distinguish absolute volume from percentage. |
| Which dimensions make up the profile? | Radar for a few comparable axes and series; grouped bars, dots, or a heatmap when precise comparison dominates | Radar rules below; show the underlying values, denominator, and primary differences. |
| What is the shape of a numeric measure? | Histogram, ECDF, box/interval plot, or individual dots for small n | Report bins or quantiles, missing counts, and cutoffs. Shared ranges/bins for comparisons; avoid unlabeled density normalization. |
| Which rules select the same records? | Area-proportional two-set Venn when verifiable; exact intersections table or UpSet when circle geometry cannot express the memberships | Use record IDs and explicit exact intersections. Do not use a radar, summed counts, or a stacked bar that double-counts overlap. |
| Where did the *same* records move? | Label transition matrix for exact source→target counts; Sankey for a readable flow; paired table if small | Fixed left→right direction; show diagonal, no-change and unmatched coverage. Check row/column totals; do not link unrelated margins. |
| What contributes to a net change? | Waterfall for additive components; grouped repair/regression counts or paired transition table | Positive and negative changes must reconcile. For model gains, list fixed, regressed, both correct/wrong and ineligible separately as applicable. |
| Where are counts concentrated by two categories? | Heatmap with in-cell counts or aligned table | Name row/column denominator when shading proportions; keep the color scale consistent. |
| Do two numeric measures move together? | Scatter; binned scatter or hexbin for dense points | Axes, scale, valid n and outliers; association is not causation. |
| Where did cases drop out of sequential stages? | Funnel or connected bars, stage table | A funnel assumes stage order and nested eligibility, not parallel screening rules. Show both overall and previous-stage rates when useful. |
| Is the estimate sufficiently precise? | Point and interval plot | State confidence/credible level, method, sample size and pairing; don't invent intervals from unavailable inputs. |

## Radar: profile, not a substitute for a count chart

- Choose it when the eye should compare *shapes across the same axes*. Roughly 3–8 axes and 2–4 overlapping series are a useful starting point, not a prohibition. Use small multiples for more series; use bars/dots when exact differences matter more. If the user requested one five-axis pool radar, the five axes are pools, not five independent charts.
- For cohort distributions of five mutually exclusive pools, each series is the five pool shares within its own named cohort (for example quality-score rejected vs retained). Show cohort n, counts/share table, the shared order/radial bounds, and excluded/missing counts. Verify the included shares reconcile under the declared denominator. Multilabel rates can legitimately sum to more than 100%; label them as such.
- For mixed metrics, use fixed, meaningful normalization bounds and consistent direction across series; disclose raw values, formula, bounds, and lower-is-better reversals. If normalization would be arbitrary, show separate aligned panels instead. Preserve geometry across filters. Do not turn null into a zero point or compare polygon areas as a metric.
- Derive positions and text from the same data: for axis index i with k axes, angle is 2πi/k − π/2, distance is the common-scale fraction times the plotting radius. Use a shared center and radius, consistent scale ticks, distinguishable line styles, direct labels or a visible legend, and an adjacent exact-value table. Don't hardcode plausible-looking polygon coordinates.

## Venn and UpSet: make membership exact

- Define the universe U and each membership rule, deduplicate within the relevant key, distinguish not scored / unknown from explicit rejection, and state the common evaluation population. If eligibility differs, compare the common evaluable population and account for the rest separately; “neither” is calculable only with a defined U.
- Two sets: show A only, A∩B, B only, and neither when relevant; check `|A∪B| = |A| + |B| − |A∩B|`. In three sets, label each exclusive region, including triple overlap. Distinguish “A and B, irrespective of C” from “A and B only.” Do not infer overlap from marginal totals.
- A two-set quantity diagram uses circle **area**, not radius or diameter: choose one factor k, then rA = √(k·|A|/π), rB = √(k·|B|/π). Solve the center distance so the shared lens is k·|A∩B|; then A-only and B-only also have the correct areas. Use a uniform x/y scale (SVG viewBox preserving aspect ratio). For disjoint sets show a gap; for containment draw the smaller circle wholly inside the larger; for equal identical memberships show one coincident geometry. Do not pad small circles, widen a lens for a label, or hand-tune overlaps.
- Recompute areas from the rendered radii and spacing in the same unit and enforce a declared numeric tolerance. For 3 sets, circle geometry is **not generally able** to fit arbitrary exclusive regions: show it only if every region, including the triple and the three pair-only lenses, is validated against the same area scale. Otherwise, or if geometry/counts are missing, inconsistent, nonverifiable, or too extreme to read accurately, omit the circles. Use an exact intersection table for a few combinations or an UpSet-style membership matrix with aligned bars for many. Explain missing breakdowns; never infer intersections from marginals or use a schematic in place of a quantitative chart.
- For 4+ sets, prefer observed exact combinations ranked as bars with a membership dot matrix (UpSet pattern); distinguish hidden long tail from zero. Test exclusive regions sum to the eligible universe including the neither group where defined. Zero-size groups remain explicit in the table; “neither” and “unknown” are not Venn lens regions.
- Bind each shape, table button, or combination bar to the corresponding exact predicate/IDs. Give touch/keyboard users the same route from labeled adjacent controls or the table.

Reference for the matrix/bar encoding: [Lex et al., UpSet: Visualization of Intersecting Sets](https://vcg.seas.harvard.edu/publications/20140101-upset-visualization-of-intersecting-sets).

For a Node-based report builder, [chart-data.mjs](../scripts/chart-data.mjs) is an optional helper. It returns exact membership regions with IDs (string keys), missing-rule records, verified two-set circle geometry (or an explicit non-drawable reason), and radar coordinates. Use the resolved data for the chart, exact table and drill-down, then embed it in the final offline file. Run its embedded fixtures using `node scripts/chart-data.mjs --self-test`.
