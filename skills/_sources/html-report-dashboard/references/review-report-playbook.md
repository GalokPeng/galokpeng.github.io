## 1. 先确定交付模式

| 模式 | 目标 | 可组合的视图（不等于固定标签页） |
| --- | --- | --- |
| 汇报型报告 | 让读者先得到结论，再追溯证据 | 总览、分布/趋势、差异归因、口径 |
| 模型对比 | 比较多个 run 的准确率、稳定性和流向 | 总览、版本矩阵、流向/差异、数据详细、口径 |
| 人工复核 | 逐条修改、导入、导出标签 | 统计、复核页、Prompt/标签说明、导入导出 |
| Prompt 审计 | 解释改了什么、为什么改、哪些样本验证 | Prompt diff、数据验证、结论、口径 |

用户只要求“纯 HTML”时，默认不启动服务器、不依赖 Vite/CDN，并把所有必要数据内嵌或以可下载附件形式提供。

## 2. 数据清单与对齐

在生成任何指标前，建立 manifest。至少记录：

```json
{
  "dataset_id": "evaluation-set-a",
  "dataset_label": "Evaluation Set A",
  "source_path": "/absolute/path/file.jsonl",
  "sha256": "...",
  "row_count": 320,
  "parse_ok_count": 319,
  "invalid_count": 1,
  "id_key": "id",
  "join_coverage": 1.0,
  "model": "...",
  "prompt_version": "prompt-version-or-null",
  "prompt_sha": "...",
  "parameters": {"temperature": 0, "thinking": false, "batch_size": 5}
}
```

- 用稳定 ID 对齐；绝不按行号或文本顺序静默 join。若只有 `idx`，先显式记录这是降级键。
- 支持直接 JSON、JSONL、`pred`/`gold` 嵌套 JSON 字符串；解析失败必须成为一类可筛选记录，不能丢弃或当作正确。
- 检查重复 ID、重复文本、重复文本的标签冲突、缺失 ID、左右集合不一致，并在总览显示数量和比例。
- 保留 `raw` 原始对象和 `normalized` 规范对象；规范化只做字段映射、空值处理和集合排序，不覆盖原值。
- 同一模型的多个 run、同一 Prompt 的不同 run、不同模型/Prompt 必须有稳定的 `run_id` 和可读标签，不能只显示 M1/M2。
- 文件名与内容版本冲突时，以 manifest 警告呈现，不要自行猜测版本；显示“可计算”和“无法确认”的边界。

## 3. 标签与真集口径

先写 schema，再写 UI 和指标：

- 分类/等级/池子是单选还是多选必须明确；人工允许标签集合与模型单标签不能混成普通字符串。
- 任意集合字段（例如属性标签、风险标签或价值标签）应保留原顺序与规范化集合两份。
- 解释、建议、reasoning 等长字段只读展示原文；项目存在 `core_value`、`architect_advice` 等字段时按同样方式处理，不用关键词或正则反推标签解释。
- 标签说明必须来自对应版本的正式 Prompt 或已批准的标签规范原文。输出完整标签名、中文含义、命中条件、边界/例外；缺说明时显示“Prompt 未提供说明”，并列入数据质量问题。
- 不能把代码或内部缩写当成完整解释；例如项目字段出现 `D07`、`Q_VisualDependent` 或“不打 Q”时，应显示正式全名和来源定义。

### 指标最低要求

每个指标旁边写出公式、分母、真值来源、缺失处理和容忍规则：

- 严格类别准确率：`预测类别 ∈ 人工允许类别集合` 的记录数 / 有效对齐记录数。池子只是该模式的一种实例。
- 容忍类别准确率：严格命中，加上配置中明确允许的有向/无向边界；每条边界可独立勾选，不能隐式放宽。
- 单标签字段：exact accuracy；多标签字段：set exact、precision、recall、F1、Jaccard 视需求分别计算。
- 稳定性：同一 `dataset_id + record_id` 在多 run 的标签相同率；与准确率分开，不能用“重复一致”代替“正确”。
- 差异：按交集计算；另外列出仅左侧、仅右侧、解析失败和重复 ID，不能把不匹配样本当作错误标签。
- 禁止将单标签准确率命名为 F1；没有可信字段真值时，显示准确率“不可计算”；模型之间仍可报告一致率，不得把它冒充真值准确率。
- 版本总览同时给严格、容忍、解析率、覆盖率和样本数；不要只给排序后的单一分数。

## 4. 多版本差异应如何呈现

按用户提出的比较问题挑选以下视图，不为每个版本机械复制同一报告：

1. 逐版本指标卡和固定顺序的对比表；保留 Prompt 版本、模型、参数、数据集。
2. 版本两两矩阵：一致、池子变化、领域变化、字段变化、解析失败、无法比较。
3. 流向汇总：`源类别 → 目标类别` 的计数、占比和样本链接；有序等级存在时，把相邻、跨两档、跨三档、双向变化分开。
4. “主标签不变”“辅助字段不变”“同时不变”筛选；在池子/领域任务中可映射为“不变池子”“不变领域”。支持只看某条流向、某个字段或某个模型家庭。
5. 有逐条证据的重要问题数字可点击到对应过滤明细；没有记录证据的结果只说明口径。具体交互见 [下钻与布局](design-and-drilldown.md)。

对于人工多轮真集，先展示每轮覆盖量和可比交集；不能把 110 条修正集直接与 320 条完整集按分母混算。若某轮只复核不一致样本，要分别报告“复核子集指标”和“全量重建后的指标”。

## 5. 复核页面交互规范

- 模型结果只读，人工修正单独存储；原标签旁明确显示“原”，不要覆盖原值。
- 类别/池子和其他允许多选的标签使用 schema 驱动的多选控件；所有合法选项直接可见，禁止把二级标签藏在无法操作的下拉层。
- 标签说明使用即时 hover/focus tooltip（不设置人为等待），不是 `window.confirm`、alert 或点击确认弹窗；键盘焦点也必须能看到说明。
- 长文和并排解释用宽详情工作区（宽抽屉、分栏或专页），按 [下钻与布局](design-and-drilldown.md) 选择。包含完整正文、相关原始模型字段、解释/建议和人工备注；长内容滚动时关键操作仍可见。
- 提供上一条/下一条、当前序号、筛选后总数；切换记录时保留筛选条件和焦点。
- 备注放在标签操作之后；输入采用 debounce 或 `change` 自动保存，不重建 textarea、不替换 DOM 节点，避免光标跳失。提供“还原本条”按钮。
- 导入/导出使用带 `schema_version`、`dataset_id`、`record_id`、`original`、`review`、`updated_at` 的通用 JSON；导入前显示覆盖条数和不匹配条数，不能用确认弹窗阻塞。
- 优先实现使用者会拿来找记录的筛选，例如数据集、版本、原/人工主标签、多选集合、等级相邻变化、字段差异、解析失败或关键词；导出当前筛选与全部数据分开。
- 长文内容可复制；UI 可截断预览，但不得截断导出或详情原文。内容摘要只有在有可信摘要字段或用户明确要求生成时才显示，并标注来源。

## 6. Prompt 展示与验证

- Prompt 独立标签页支持 Markdown 渲染，同时提供“复制正式 Prompt”；正式版本正文不夹带分析注释、diff 标记或候选说明。
- diff 必须左右并排：左侧原 Prompt，右侧候选 Prompt；按行/块高亮新增、删除、修改，并显示 Prompt SHA。
- 每个修改块对应修改原因、影响的标签/规则和验证样本；验证样本不能只有一条，至少按每个改动点提供一组正例、边界例和反例（若数据存在）。
- 标签解释从 Prompt 的结构化章节或人工确认映射中读取，不能靠标签名字的模糊正则匹配。

## 7. 纯 HTML 的性能与安全

使用 [离线与渲染规范](design-and-drilldown.md#visual-system-and-performance)。同一条正文和 Prompt 只存一份；原始模型字段按稳定键对应。未经授权，不从浏览器发起内部网络请求。
