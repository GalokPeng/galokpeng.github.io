# 03 验证与证据

## 建立与风险对应的矩阵

把每项验收行为连接到具体检查：纯逻辑、集成、真实平台、打包后、安装升级、生产冒烟。先复现或构造能暴露问题的用例；新测试应证明行为或边界，避免逐行复刻实现。低风险文字/样式调整可用视觉/静态核对，不为凑数造测试。

明确每个检查的环境与限制。离屏 UI 不能证明系统托盘、全局快捷键、多屏热插拔或真实硬件工作；模拟成功不能代替真实安装；本机通过不证明整个 OS/架构矩阵。未覆盖的目标标记 pending/受限，不能写“全面兼容”。

## 功能与故障

- 正常、空状态、无权限、离线、限流、磁盘满、取消、重复操作和异常退出。
- 旧版本数据升级、新字段默认、损坏配置回退、用户选择保留。
- 子任务超时与迟到结果；关闭/退出期间的资源释放；并发实例与共享资源恢复。
- 后端的超时、幂等、鉴权、错误响应、迁移失败；库的旧 API、类型和实际安装导入。
- 对声明支持的语言、主题、输入法、Unicode/空格路径、高 DPI、窄屏、键盘导航做必要验证。

## 分发物验证

在干净或隔离环境直接运行拟发布制品，移除开发机 PATH/全局依赖的掩盖。验证架构/最低系统、配置与资源、相对路径、动态库/插件、关键功能、离线行为和日志。检查实际包内容，代码测试不能发现打包时漏掉的资源。

构建校验从受控清单推导平台、资源与必要组件，避免 UI、打包和测试各自写死一套旧名称。清单错误、缺文件或摘要不符直接失败；校验器自身也应有损坏/遗漏输入用例。

验证最终字节：签名、压缩、安装包封装之后重新计算大小与摘要。测试旧构建后重新编译再上传，会使先前的制品证据失效；应测试最终输出或说明哪部分可复用、哪部分必须重验。

## 安装/升级/卸载（适用）

至少覆盖首次安装、N-1→N、运行中升级、不同语言、空格/非 ASCII 路径、权限不足和卸载后的数据保留策略。必要时增加更早数据版本与降级拒绝路径。

“不同安装目录”未必隔离：AppId/包名、卸载记录、系统服务、协议/文件关联、自动启动、更新通道和系统资源可能仍共享。优先干净 VM/专用测试账号；夹具测试使用独立产品身份与临时配置，最后恢复注册项。真实身份的安装测试不得覆盖当前用户的正式安装或注册表记录。

升级流程应证明：验证下载 → 准备安装交接 → 旧进程正常退出/锁释放 → 安装完成 → 使用正确配置重启。校验失败、准备失败、安装取消与失败也要有明确定义。不要拿“安装器进程成功启动”代替升级成功。

## 视觉与隐私

使用隔离演示配置、虚构条目和有权分发的素材。确认截图没有个人桌面、通知、路径、头像、文件名、剪贴板、访问令牌和图片元数据。分别检查图片文件本身与页面实际显示；截图裁剪坐标注意逻辑像素、物理像素与 DPR。

## 记录与解释结果

证据包括候选提交/制品摘要、命令或平台任务、环境、观察时间、结果与可查日志/地址。多仓库记录各自提交，不能将某个仓库绿灯挪用给另一个。

已通过检查在同一输入与环境下无需不断重跑。发生新改动、新失败或覆盖缺口时再针对性扩展。失败需要分类为实现缺陷、测试缺陷、环境/平台条件、外部网络或已证实的非确定性；不能把未解释失败称作“偶发”并重跑到绿。保留初次结果与修复/重试依据，不降低断言掩盖问题。
