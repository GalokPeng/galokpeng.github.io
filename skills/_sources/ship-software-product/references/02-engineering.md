# 02 工程、性能与数据边界

## 实现完整用户路径

对有状态操作检查：空状态 → 正常执行 → 成功反馈，以及失败、重试、取消、重复点击、并发请求、关闭、崩溃与重新启动。状态必须反映已完成事实，不能仅因为发起操作就保存“已应用/已完成”。

异步结果携带请求/会话标识。旧任务迟到时不覆盖新状态；取消后不自动复活。重试具有幂等键或去重边界，特别是付款、邮件、任务提交和外部写入。把用户可见状态与底层任务生命周期明确连接。

## 测量后划分性能边界

给目标场景选少量指标：启动耗时、交互延迟、工作集/峰值、空闲 CPU、CPU/GPU、帧率、I/O、网络、包体或服务吞吐。标明环境、数据规模、样本和测量方法，不把单次数据写成性能保证。

UI 主线程和请求处理路径不能等待长时磁盘/网络/媒体解码/大批量原生调用。按可取消性、隔离性与通信成本选择异步 I/O、线程、任务队列或子进程；不要默认所有工作都要开进程或改语言。

- 后台任务要有启动/控制/退出超时、容量上限、失败反馈和清理。
- 缓存需规定键、失效条件、容量/淘汰、原子写入和损坏恢复；未校验的缓存不能冒充最终文件。
- 批量处理设置时间/数量预算；避免重复读取图标、全盘扫描、UI 重建和无变化的刷新。
- 动效服务于反馈与空间关系。尊重系统减少动态效果设置；避免高频输入的长动画。装饰效果空闲时降低或停止绘制，关闭时释放监听。
- 图片/视频变换遵守用户画质约束。缩略图与预览不能替代原文件；自动降采样、帧率/编码改变需明确。

## 生命周期与原生接口（适用时）

定义每个句柄、回调、订阅、线程、子进程、GPU/解码资源的拥有者和释放顺序。先停止新任务，再取消/隔离旧回调，最后释放资源；关闭窗口不必等于停止已授权后台任务，完全退出则应按约定清理。

不能把对象仍有 Python/JS 引用等同于底层对象仍有效。GUI/原生对象销毁期间的迟到回调需验证对象、会话和依赖资源仍存在。屏幕/显示设备、Shell、窗口、音频设备与宿主进程重建时重新取得当前对象，不复用失效包装器。

使用 FFI 时核对调用约定、结构布局、位数、所有权、线程亲和性、字符串编码与错误返回。某些封装会缓存可变函数签名；不同调用方不能互相覆盖结构类型声明，可使用统一定义或独立绑定。不要以工具能调用未公开接口来承诺所有系统版本兼容。

共享系统状态采用租约/互斥、原值记录、幂等恢复和所有权检查；多个数据配置目录不等于多个独立的系统会话。故障测试应证明父进程异常退出后不留下子进程、热键、系统外观或隐藏状态。

## 配置与用户数据

区分安装目录、可写配置、缓存、临时文件、日志、密钥、用户原始文件。按平台规范和用户选择确定位置；安装目录不可写时有明确策略。不要将用户数据加入源码、构建上下文、安装包或官网。

配置加载需类型/范围校验；新字段有兼容默认，已有合法选择保留。数据库/格式升级记录 schema 版本、迁移顺序、事务/恢复点；副本备份本身也属于敏感数据，应遵守保留与清理策略。

导入、收纳、同步、重命名、删除需明确“引用/复制/移动”的区别。处理部分失败、重复名称、符号链接、路径穿越与中断恢复。不覆盖原始资源，不用恢复操作销毁用户后续修改。清理缓存只处理确实由当前产品拥有的条目。

保密信息放平台凭据库或受控 secret 服务。日志对 token、Cookie、签名 URL、个人路径与正文最小化/脱敏；诊断模式默认不上传数据。
