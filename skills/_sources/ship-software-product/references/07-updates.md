# 07 软件内更新、下载与安装交接

仅当产品需要自更新时实施；由应用商店或系统包管理器管理的软件应遵循其机制。不能为了展示“自动更新”私自覆盖受管理安装。

## 可观察状态

检查中 → 已是最新/可更新 → 下载中 → 验证中 → 准备交接 → 退出/替换 → 安装完成 → 正确配置重启。失败和取消要有独立可重试状态，不能把“启动安装器”当成“安装完成”。

UI 显示进度：已知总大小时百分比，未知时字节与活动状态；换源从头下载时解释进度重置。下载成功前不退出；交接准备失败时保留应用运行。是否允许关闭设置后继续下载按产品约定，完全退出/取消则清理任务。

## 元数据与信任

识别产品、版本、稳定/预发布渠道、OS、架构、包/安装类型、最低兼容版本、URL、大小、摘要和必要签名。不要给 ARM 用户下载 x64，或向稳定渠道推送预发布。

版本采用项目真实比较规则，处理重复、降级、预发布、回滚与元数据过期。高风险更新系统考虑签名元数据、过期时间和抗回滚/冻结机制；优先成熟平台方案，而非自制未审查的密码协议。

HTTPS 与 SHA-256 校验完整性并不自动证明发布者：若文件和校验值都可由同一不可信来源替换，攻击仍可通过。摘要应来自受信任发布元数据，必要时增加发布签名/平台验证与密钥轮换；不要把 MZ、MIME、文件扩展名当成安全验证。

## 有界下载

使用流式读取，限制总大小、并发、超时、跳转次数和缓存容量。拒绝 HTML/错误页、异常长度、错误版本/平台、摘要不符和不允许的目标。下载临时文件，完成校验后原子改名；缓存再次使用前校验。恢复下载需验证 Range/ETag/对象身份，避免拼接不同版本。

官方与镜像策略显式可见。镜像有可用性和隐私权衡；只向其发送下载所需信息，不转发 token、Cookie 或私有仓库地址。官方版本身份与摘要不能跟随不可信镜像改变。重定向跨源需校验预期发行商/CDN范围，不能开放代理任意 URL。

测试断网、慢速、限流、半包、错误摘要、磁盘满、缓存损坏、切源、取消和校验失败。只切换到已配置来源，失败后留下可诊断信息，不能执行半包或无限重试。

## 安装版、便携版与源码

安装版只有在确认产品身份、当前可执行文件和登记安装目录一致时，才做同目录自动升级。便携版不能接管机器上另一份正式安装；按产品约定选择便携替换或打开安装向导。源码运行通常提示构建/安装流程，不改开发环境。

安装辅助程序放在更新缓存/临时位置，避免被替换的目录锁住自身。交接验证下载物与目标目录，建立 ready 握手并持有可靠的父进程身份/句柄，等待旧进程退出再替换；不能仅凭可复用 PID 判断。

清理旧进程、工作任务和文件句柄；独立重启环境，避免继承冻结运行时、DLL 搜索路径或错误配置。重启同一安装与正确用户数据，不把缓存目录当成配置。提升权限时重新验证目标与完整性，抵御路径/文件替换竞态；优先 OS/成熟更新框架。

升级不应要求用户另装本应随包提供的运行组件。确有平台或许可限制时，在安装/产品说明中明确提供合规处理，而不是运行关键功能时才暴露开发依赖缺失。

## 端到端证明

同一桌面产品同时提供商店和独立安装时，按实际包身份分流。商店版经商店更新；独立安装版使用其已配置的更新器。分别验证旧的同渠道安装可以更新，且不会拉起另一渠道的安装程序。若产品承诺跨渠道迁移，再单独验证身份、注册项和数据迁移。

使用独立产品身份的安装夹具或干净设备，通过真实下载状态、校验、退出、安装、保留数据与重启断言证明流程。最终再检查公开版本化地址、latest 入口和客户端实际元数据的版本/摘要一致。
