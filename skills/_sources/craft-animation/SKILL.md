# 动画创作工坊

先确定观众应当看懂哪一个变化，再决定用什么来画。把能修改的源文件留在工作项目里，让下一位 Agent 能按时间点重做镜头。

下载 ZIP 后，将整个 `craft-animation/` 目录放入 Agent 的技能目录。Codex 项目可放在 `.agents/skills/`。例如可以说「用 `$craft-animation` 做一段六秒的机械开花动画，花瓣随齿轮逐层打开」。

## 从意图到镜头

- **新作**。从用户的措辞提取主角、起始状态、变化原因与落点。对「有重量」「更液态」「像印上去」这类描述，写成能在画面里看见的动作。例如「纸张右缘先接触桌面，左角比中部晚落两帧」。已有画幅、参考图、品牌轮廓、色彩或交互要求时沿用它们。
- **改片**。找到用户指定的版本，截取问题发生前、发生时、发生后的几帧。区分要改的造型、轨迹、摄影机和材质；保留已经认可的节奏、声轨和镜头。若只有压平的视频，先判断能否从现有工程重渲或对局部遮罩合成，确认实际可编辑的范围。
- **编排**。为关键事件记下秒数或帧号、事件发生的位置、哪个物体先动、另一个如何响应。状态交接要在同一坐标与时间发生，例如笔尖到达纸面的那一帧，线从笔尖下方生长。测试循环时也检查最后一帧接到第一帧的速度与方向。

## 选择制作方式

| 镜头的关键要求 | 合适的实现 |
| --- | --- |
| 网页需要随点击、拖动、滚动改变进度 | HTML/CSS、SVG、Canvas 或 WebGL。把状态或进度作为输入，检查中断、反向和减少动态效果。 |
| 平面图形、机械运动、文字或图表需要精确落点 | 用关键帧、路径和遮罩；可用现有矢量工具或随包的 Python 逐帧入口。 |
| 大量像素共享同一套光照、折射、噪声或场函数 | 用 GLSL 在显卡渲染；随包提供可运行的单通道片元着色器。 |
| 需要骨骼表演、真实空间遮挡、绕拍或复杂布料 | 在现有 3D 工程中处理层级、绑定、灯光和相机。锁好接触点后烘焙，再从渲染帧合成。 |

需要处理拖尾、表演、摄影机、撞击或印染时，按问题查阅[动作、材质与镜头](references/motion.md)。工具随项目选择；渲染入口适用于需要导出固定帧率影片的分支。

## 做出第一段可看的动作

先渲染信息量最大的几秒。用缩略图查轮廓与遮挡，再按原速播放判断停顿、重量和节奏。下面的绘图机是一个独立例子：一支笔装在滚轮上，笔尖走过的位置留下曲线。可以换掉整个场景。

在解压后的 Skill 目录运行。命令需要 Python 3.9+、带 libx264 的 FFmpeg 和 Pillow。将输出路径换成项目内的工作目录。

```sh
python scripts/render_scene.py assets/drawing_machine.py out/study.mp4 --seconds 6 --fps 30 --size 960x540
python scripts/review_frames.py out/study.mp4 out/poses.png --frames 0 30 75 120 170
```

Python 场景和 GLSL 场景的接口、GPU 样例、声音对齐及网页轻量导出见[渲染与交付](references/delivery.md)。已有 Blender、浏览器或其他工具的成片也可以直接用第二条命令检查。

## 交付前看什么

- 在转向、接触、遮挡切换、定帧和循环接缝附近查看相邻帧，再以交付速度完整播放一次。暂停画面能看清形状，实时播放才能判断因果。
- 点名的问题要在**交付文件**里复查。例如对「接触那一刻出声」，同时核对画面接触帧与音频瞬态；对「终帧是原标志」，叠对原始轮廓，单独看边缘和负空间。
- 按媒介验证。影片核对尺寸、显示帧数、时长和所需声轨；交互作品在实际输入设备上试触发与中断；网页循环在慢网、移动视口和减少动态效果下检查实际加载的资源。
- 交给用户可直接观看的成品。需要后续迭代时附上可编辑场景及重渲命令。用户只要预览时，先把样片交在本地。
